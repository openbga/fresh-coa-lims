{% comment %} A record page's layout (docs/ui-standards.md, HIERARCHY.md "Record layout"): the first panel with the side column beside it; the body's panels keep stacking in the left column for as long as the side column runs beside them and take the full width once it has ended, so a tall side column leaves no gap. Panels in the wide part (genuinely wide tables) always go full width below the side column. The side column holds the launch panel of the most frequent record action (Add sample, Record result). It grows with its content up to the viewport height; longer content scrolls inside its own box, a keyboard-focusable region named by aside_label, with a visible scrollbar and a fade while more remains below. When the record is narrower than 60rem (a phone, a tablet, the open help drawer) everything stacks in reading order: first panel, side column, the body, the wide part. DOM order is always the reading order. Rendered by the {% record_layout %} block tag ({% load ui %}); the body is the following panels. Parameters: aside_label accessible name of the side column's scroll region (e.g. "Next step") Parts: lead the first panel (the record's key facts) aside the side column; omit it for a single column wide panels that need the full width (wide tables), after the body, below the side column Usage: {% record_layout aside_label="Next step" %} {% fill lead %}{% panel title="Lot" %}...{% endpanel %}{% endfill %} {% fill aside %}{% if can_record %}{% panel title="Next step" id="next-step" %}...{% endpanel %}{% endif %}{% endfill %} {% panel title="Receipt" %}...{% endpanel %} {% history_panel events=history %}{% endhistory_panel %} {% fill wide %}{% panel title="Supplier certificates" table=True %}...{% endpanel %}{% endfill %} {% endrecord_layout %} {% endcomment %}
